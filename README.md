# 시장이 보는 정책금리 변경 확률

<https://tskang89.github.io/policy-odds/>

조간 브리핑 맨 아래 '참고자료'에 걸리는 쪽이다. 차트팩·일정표와 같은 꼴로
만들었고, 평일 새벽에 새로 만든다.

세 중앙은행(연준·ECB·일본은행)의 앞으로 약 석 달 안 회의마다,
**그 시점에 정책금리가 오늘보다 낮을·같을·높을 확률**을 싣는다. 셋의 합은
100 이다. 그 회의에서 새로 움직일 확률이 아니다 — 뒤 회의 칸에는 앞 회의에서
움직일 가능성이 이미 들어 있으므로 칸끼리 더하면 안 된다.

## 출처

| | 출처 | 격 |
|---|---|---|
| 연준 | CME 페드워치 | 거래소가 선물로 계산해 공개 |
| ECB | Central Bank Watch | 제3자가 €STR·OIS 선물로 계산해 공개 |
| 일본은행 | Central Bank Watch | 〃 |

**셋 다 남이 계산해 공개한 수치다.** 이 쪽에 내가 계산한 숫자는 없다.

CME 가 €STRWatch 를 유료로 돌려 ECB 를 그쪽에서 받을 수 없다("You do not
have access to this feature", 2026-10-05 확인).

`www.cmegroup.com` 은 Akamai 가 코드 접속을 막는다(403). 페드워치 도구 자체는
`cmegroup-tools.quikstrike.net` 에 올라가 있고 그쪽은 막혀 있지 않다.

## 한국은행을 뺀 까닭 (2026-10-06, 소장님 지시)

한국은행은 공개 확률 지표가 없어 통안증권 91일 금리에서 **역산**해 실었다.
91일 금리를 그 사이 하루짜리 금리의 평균으로 보고, 그 안에 든 모든 금통위가
같은 크기씩 움직인다고 가정해 누적 변화폭을 풀고 25bp 한 칸으로 나누는
셈법이었다.

**관측이 하나뿐이라는 것이 한계였다.** 총량은 정해지지만 첫 회의 몫인지 둘째
회의 몫인지는 가릴 수 없다. 가정 하나를 얹어야 숫자가 나오는데, 거래소가
선물로 낸 연준 수치와 같은 표에 나란히 두면 같은 무게로 읽힌다. 화면에
'역산' 띠와 범위 각주를 달아도 그 차이는 전해지지 않는다.

셈법은 git 이력의 `build/bokcurve.py` 에 남아 있다. 되살릴 일이 있으면
`make.py` 의 `collect()` 에 한 줄을 더하고, 아래 두 가지를 다시 챙겨야 한다.

- **ECOS 비밀값** `ECOS_API_KEY` (저장소 Settings → Secrets, 워크플로 env)
- **1년 금리는 셈에 넣지 말 것.** 처음에 91일 창 안 회의를 하나만 넣고 둘째
  회의를 1년 금리로 풀었더니, 1년 금리에 든 내년 인상까지 둘째 회의 한 번에
  몰려 11월 인상 확률이 100 으로 나왔다. 창 안의 회의를 모두 세고, 통안
  91일의 평소 프리미엄 **+2.5bp**(2013~2026년 3,388 영업일 중앙값)를 빼야
  78.2% → 43.2% 로 제자리를 찾았다.

## 돌리기

```
pip install -r requirements.txt
python build/make.py          # index.html 을 새로 쓴다
python build/make.py --check  # 쓰지 않고 만들어만 본다
```

비밀값이 필요 없다. 셋 다 공개 쪽을 읽는다.

## 짜임

```
build/fetch.py      공통 받아오기 · 확률 합을 100 으로 맞추기
build/fedwatch.py   연준 (QuikStrike 되돌림으로 회의를 넘겨 가며 읽는다)
build/cbwatch.py    ECB·일본은행 (쪽에 심긴 분포 JSON 을 읽는다)
build/make.py       쪽 만들기
template.html       틀
```

한 곳이 실패해도 나머지는 올라가고, 빠진 것은 화면에 적는다. 세 곳이 다
실패하면 쪽을 쓰지 않는다 — 빈 쪽을 올리면 '시장이 아무것도 안 보고 있다'로
읽힌다.
